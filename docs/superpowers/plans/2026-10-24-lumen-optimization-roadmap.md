# Lumen 优化路线与实施方案（2026-10-24）

## 背景

本轮对话已经把截图、贴图、素材库、安装器等核心链路稳定下来。本文记录后续可执行的优化项、优先级与验收方式，并固化本轮新增的三项交互决策：

1. 主窗口外围使用 1px 淡灰色边框，与白色背景的文档窗口区分；不再依赖 Windows 系统阴影。
2. 标题栏窗口按钮排列改为 Windows 习惯：最小化、最大化/还原、关闭，放在标题栏右侧。
3. 贴图支持 Ctrl + 滚轮调整整体透明度（步进 5%，范围 10%–100%），普通滚轮仍然缩放；调整时显示百分比徽标。

同时移除了应用内远程更新检测：启动不再请求更新服务，关于页只显示版本号、复制信息、打开文件夹与清理图片缓存。发布更新改为用户手动下载安装包。

## 本轮新增项的验收

| 项目 | 验收方式 |
| --- | --- |
| 淡灰边框 | 运行应用后读取 `.library-root::after` 的计算样式，确认 `box-shadow` 为 1px inset 且颜色非白色；对比白色文档背景可见边界。 |
| Windows 按钮顺序 | 检查标题栏 DOM 顺序为 最小化 → 最大化/还原 → 关闭，且整体位于右侧；最大化/还原图标随窗口状态变化。 |
| Ctrl + 滚轮透明度 | 创建贴图后用 Ctrl+滚轮上下滚动，贴图整体透明度随之变化，徽标显示当前百分比；普通滚轮仍只缩放。 |
| 移除更新检测 | 启动后日志中不再出现任何更新服务请求；关于页不出现检查更新按钮或更新状态。 |

## 进度记录

### 2026-10-24：背景装饰改为蓝色丝带

素材库主工作区最初使用一层极淡的浅灰纸纹，视觉上仍像空白的白纸。现在改为蓝色绸缎丝带背景：由 Agnes Image 2.5 Flash 生成 2K 丝带图（提示词明确要求“flowing translucent royal-blue satin ribbons”“silky ribbon curves”），压缩为 1920×1077、约 125 KB 的 JPEG，通过 58%→68% 白色渐变蒙层铺在 `.library-workspace` 上。卡片、列表、工具栏保持不透明，正文对比度不变。

验收：发布版计算样式为 `linear-gradient(rgba(255,255,255,0.58), rgba(255,255,255,0.68)), url(".../assets/ui-background-ribbon-*.jpg")`，界面截图确认丝带可见且空状态文案清晰。

### 2026-10-24：P0 第一批完成（1.6.31）

- 贴图右键菜单补全：复制图像、另存为 PNG…、保持置顶、锁定位置、关闭、关闭全部贴图。复制与保存走后台线程，菜单文案随七种语言切换。锁定后拖拽、边缘缩放与方向键移动都不再改变位置，缩放仍然可用。

### 2026-10-25：贴图缩小画质修复（1.6.32）

贴图缩小时文字发糊，根因是缩小采样把每个目标像素对应的源范围向上取整，90% 这类轻微缩小时会多平均一整列/行未被覆盖的源像素，使 1 像素宽的文字笔画对比度掉到约一半。

现在改为按真实覆盖面积加权的缩小采样：每个目标像素只累计实际重叠的源像素，并按覆盖比例加权；1:1 仍直接使用原图，整数比例（如 50%）与原先的平均结果一致。新增回归测试：100→90 缩小时单像素白线亮度保持 ≥220/255，均匀色块缩小到 8/7/5/3 像素宽后亮度不变，多线程与单线程结果仍逐字节一致。

### 2026-10-24：发布版性能基线（1.6.31）

在同一台机器上用发布版（`src-tauri/target/release/kiri.exe`）测量，作为后续 P2 优化的对照：

| 指标 | 结果 |
| --- | --- |
| 主窗口出现（进程启动 → 窗口句柄可用） | 136 ms |
| 主进程常驻工作集 | 38.6 MB |
| 主进程 + WebView2 子进程工作集 | 350.7 MB（7 个进程） |
| 剪贴板贴图创建（含第二个实例转发与窗口出现） | 97 ms |

这些数字是基线，不是目标；贴图低分辨率预览与按需解码尚未实现，后续优化需要复测同一组指标。

## 后续优化清单

### P0（低成本、用户感知直接）

1. 贴图右键菜单补全：复制图像、另存为 PNG、锁定位置、关闭全部贴图。
2. 贴图双击恢复 100%；Ctrl+0 恢复 100%；Ctrl+方向键 1px 精调。
3. 记忆上次截图区域，按 Enter 重复上次区域截图。
4. 托盘菜单增加直达项：截图、贴图、开始录屏、打开素材库、清理图片缓存。

验收：每项都用现有 Windows 原生探针脚本覆盖一次；贴图菜单项通过右键菜单实际点击验证。

状态：P0 四项全部完成（见 1.6.31 记录）。右键菜单的“打开”和命令执行路径已由脚本验证，菜单项文案由单元测试覆盖；实际用鼠标点选菜单项仍需人工确认一次。

### P1（体验提升）

1. 贴图多选：Shift 点选多张后批量移动或关闭。（未开始）
2. 贴图悬停工具条：透明度、置顶开关、复制、保存。（Windows 原生贴图已由右键菜单覆盖同等能力，悬停工具条不适用；WebView 贴图未新增）
3. 素材库：按日期分组、批量导出、显示磁盘占用；回收站支持全部恢复。（前两项与回收站恢复原本已实现；本轮在标题栏补充“素材库占用”，随语言本地化）
4. 录屏：开始前的显示器/窗口/区域切换更直接，增加麦克风实时电平。（未开始）
5. OCR：识别结果临时面板，支持多次识别后统一复制。

验收：涉及布局的项按窄/默认/宽三种宽度渲染并检查溢出；拖拽与选择行为用原生鼠标事件探针验证。

### P2（性能与工程质量）

1. 贴图缩放拖动时先显示低分辨率预览，松手后再出全尺寸，降低内存峰值并提升跟手度。
2. 大图贴图按需解码：先缩略图后原图。
3. 将“点击选中 + 方向键移动 + 拖拽后 ESC 关闭”固化到 Windows E2E 回归脚本。
4. 建立启动耗时与常驻内存基线，每次打包前执行一次。

验收：记录优化前后的启动时间、贴图打开耗时与内存占用对比；E2E 脚本纳入发布前检查。

### 暂不引入

- 云同步与账号体系：与本地优先、截图不上传的产品原则冲突。
- 自动下载第三方媒体工具：与只用系统媒体 API 的约束冲突。

## 实施顺序建议

先做 P0 四项，每项独立提交、独立验证；随后处理 P1 中贴图多选与悬停工具条；P2 与性能测量穿插在每次打包前执行。每轮完成后更新本文件的验收记录。
